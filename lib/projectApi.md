# 프로젝트 API와 Mock

화면은 `lib/projectApi.js`의 함수를 사용한다. `NEXT_PUBLIC_AUTH_MODE=mock|live` 설정으로 요청 출처만 바뀐다. live는 기존 `apiRequest`와 HttpOnly 세션 쿠키(`credentials: include`)를 사용한다. 라이브러리나 인증 정책은 추가하지 않는다. Mock은 브라우저 전용이다.

- 4·6·7~10·18·21~34·43·44 중 프로젝트 흐름에 필요한 요청을 제공한다. 35번은 사용하지 않는다.
- 26·27·28: SAVED 기록 = 카드 1장. DRAFT는 목록·기록 수에서 제외한다.
- 22번 데이터베이스에는 `sourceRecords`, `deletedRecordCount`가 남아 있다. 응답 필드명을 유지하면서 1:1 관계로 동작한다.
- 역량 ID는 mock 전용 fixture다. 화면은 `/competencies`에서 받은 ID를 사용해야 한다.

## 11/11 백엔드 안내 반영 — 기록 AI 질문

1. 28번 PATCH에서 `memo`를 전송·수정할 수 있다.
2. 27번은 메모·첨부가 없어도 `aiOrganize: true`로 DRAFT를 생성한다. 직접 저장(`false`)의 5칸 또는 첨부·역량 태그 검증은 유지한다.
3. 30번은 `{ mode: "AUTO" | "CONTINUE" | "REGENERATE" }`를 전송한다. 일반 진입은 AUTO, 이전 질문 유지는 CONTINUE, 새 질문 생성은 REGENERATE다. 임시 `regenerate` 필드는 사용하지 않는다.
4. 응답에 `insufficientMaterial`이 포함되고, 각 질문에는 `sourceAttachmentId`와 `answer`가 포함된다. 자료가 부족하면 `insufficientMaterial: true`, `questions: []`다.
5. 자료 변경 후 AUTO의 `409 MATERIAL_CHANGED`를 받으면 CONTINUE 또는 REGENERATE로 다시 요청한다. UI에서 재생성 성공 전에 기존 답을 지우지 않는다.

Mock은 회고 17번처럼 메모·첨부 ID를 비교한다. 모두 미답변이면 AUTO로 새로 만들고, 답변·건너뛰기가 있으면 `error.detail.answeredCount`와 함께 409를 반환한다. CONTINUE 후에는 현재 자료를 비교 기준으로 기록한다. 실제 AI의 자료 충분성 판단은 모의하지 않으며 메모·첨부가 모두 없는 경우만 자료 부족으로 처리한다.

화면은 자료 수정 저장 후 AUTO를 요청하고, 서버의 `409 MATERIAL_CHANGED` 응답을 받았을 때 기존 확인 UI를 표시한다. 취소·CONTINUE·REGENERATE를 지원하고, 답 개수가 있으면 안내에 포함한다. 재생성 실패 시 기존 입력을 유지하며 새 질문을 받은 뒤에만 초기화한다. 자료 없이도 AI 요청을 시작할 수 있다. 자료 부족 응답이면 기존 기록 추가 폼(첨부·메모·버튼)을 그대로 표시하고 폼 아래에 공통 노란색 안내 박스를 추가한다. 별도 화면으로 대체하지 않고 기존 직접 쓰기 5칸을 자동으로 펼친 뒤 요청 잠금이 풀리면 첫 칸에 커서를 둔다. '5칸 직접 채우기'를 직접 선택해도 같은 입력·포커스를 제공한다. 기존 메모·첨부·직접 입력 내용은 유지하며, 빈 질문으로 AI 정리를 호출하지 않는다. 직접 작성 후 기존 검토 화면에서 역량 태그를 고르고 같은 DRAFT를 저장한다.

## 저장 및 한계

- 기존 인증 mock으로 로그인 후 사용한다. 사용자별 `sajarok_mock_v1:<id>` 한 항목에 회고·프로젝트·스토리 카드·첨부·질문을 함께 보관한다(`lib/mock/server.js`). 처음에는 빈 프로젝트 목록이다.
- 새로고침·재로그인 후 유지하고 다른 사용자 데이터에 접근할 수 없다. 회원 탈퇴 시 해당 저장소를 삭제한다.
- 파일 본문·실제 인증 토큰은 저장하지 않는다. 파일 크기·확장자·메타데이터만 검증하며 링크를 실제로 수집하지 않는다.
- AI는 고정 질문과 사용자가 입력한 문장으로 모의 정리한다. 실 AI 품질·파일 추출·CORS·쿠키는 실제 서버에서 별도 검증한다.
- DRAFT는 24시간 이후 다음 요청에서 정리한다. 프론트의 미저장 입력·페이지 복원은 UI 작업 단계에서 처리한다.

## 오류·지연 시나리오

테스트의 `createMockServerFetch({ storage, now, scenario })`(`lib/mock/server.js`)로 지연과 오류를 주입한다. `scenario({path, method, user})`는 `{delayMs, error, status, extractStatus, finishQuestions}`를 반환한다. `finishQuestions: []`는 질문이 필요 없는 마치기 응답을 재현하며, 빈 질문 세션도 저장 전까지 재호출 시 유지한다. 브라우저 mock의 `sajarok_mock_scenario`는 공통 설정과 `paths`의 경로별 설정을 합쳐 적용한다(예: 특정 `/projects/{id}/finish/draft`만 504로 실패). AI 호출 중 같은 대상의 중복 호출은 409다. 취소·타임아웃 후 mutation은 반영하지 않는다.

브라우저 개발자 도구에서 `sajarok_mock_scenario` localStorage 키에 JSON을 설정해 오류를 재현할 수 있다. 예: `{"delayMs":800,"error":"AI_FAILED","status":502}`. 테스트 후 키를 삭제한다. 실제 50초 대기는 `delayMs:50000`, 클라이언트 시간 초과는 65000ms보다 길게 설정한다. 이 설정은 mock에서만 읽고 API 요청 본문에는 넣지 않는다.

## 화면 연결 및 기능명세 재검토

- 프로젝트 목록·상세·기록·카드·포트폴리오는 동일 API 함수를 사용한다. 회고 화면의 기존 시안 데이터는 별도 범위로 유지한다.
- 첨부 호출(7~10번)과 파일 규칙(PDF·PNG·JPG·ZIP·MD·TXT, 20MB)은 회고·자소서 매칭과 함께 쓰는 `lib/attachmentApi.js`에 있다.
- H-12의 자료 종류 선택과 처리 상태는 #30 댓글의 PM 결정에 따른다. 상단에서 회의록·발표 자료·디자인·산출물 중 하나를 먼저 선택해야 파일·링크 입력이 활성화된다. 기타는 작업자 지시에 따라 제외한다. 선택한 종류는 이후 추가하는 파일 또는 링크에 적용된다. 여러 파일을 선택하면 선택 시점의 종류로 파일마다 별도 API 요청을 보내며 각각 독립된 attachmentId를 갖는다. 다른 종류의 파일은 종류를 바꿔 추가한다.
- PENDING은 '읽는 중…', DONE은 '본문 읽음', FAILED는 '본문 읽지 못함'과 공개 링크 확인·PDF/TXT 업로드 안내를 표시한다. Figma의 SKIPPED는 '링크만 저장'과 PDF 내보내기 안내를 표시한다. 메모·첨부가 없어도 AI 질문을 요청하며 자료 부족 여부는 서버 응답으로 판단한다. 읽는 중에 AI 정리를 요청하면 폴링 완료 후 자동으로 질문을 시작한다. 대기 취소·메모 수정·첨부 추가/삭제·직접 정리·폼 이탈은 자동 진행을 취소한다. 폴링 실패 시 상태 재확인 또는 대기 취소를 선택할 수 있다.
- 업로드된 항목에는 확정된 자료 종류를 표시한다. category 수정 API는 명세에 없으므로 업로드 후 변경하는 요청을 임의로 만들지 않는다. 잘못 첨부한 항목은 삭제 후 다시 첨부한다. 상단 종류 선택을 바꿔도 기존 첨부의 종류에는 영향을 주지 않는다.
- 종류를 파일 확장자로 자동 추정하지 않는다. 마치기 산출물은 기존처럼 `OUTPUT`으로 지정한다. 상태는 PENDING=읽는 중, DONE=본문 읽음, FAILED=본문 읽지 못함, SKIPPED=본문 읽지 않음으로 구분한다.
- Mock의 7번은 FormData의 file과 category가 각각 정확히 하나인지 검사한다. 첨부별 category는 조회·27번 기록 연결 후에도 유지된다. 여러 파일/여러 category를 한 요청에 넣는 잘못된 호출은 400으로 거부한다.
- H-13: 질문별 저장·입력 보존, 자료 왕복, mode 기반 재생성. 자료가 있으면 모의 질문도 첨부 종류에 따라 선택하고 근거·숫자 질문을 포함한다.
- 질문 상단 출처 영역은 해당 질문의 `sourceAttachmentId`와 일치하는 첨부의 파일명 또는 URL을 표시한다. 출처 ID가 없으면 메모 기반임을 표시하고, ID에 해당하는 자료를 찾지 못하면 파일명을 추측하지 않는다. 이전 질문 이어 쓰기에서는 기존 출처 목록을 유지하고, 새 질문을 받으면 새 첨부 목록으로 바꾼다. Figma가 SKIPPED일 수 있으므로 본문을 읽었다고 단정하는 대신 '바탕으로 물어볼게요'로 표시한다.
- H-14·H-22: 1~3개 역량 필수, 기록과 카드 1:1. 카드 제목의 대체 문구를 원본 did에 저장하지 않는다. 빈 결과는 선택적으로 추가할 수 있다.
- H-15·H-21: 완료 후에도 기록을 편집한다. 기록 수정은 카드 요약·태그·전문에 반영하고 카드 제목·배운 점은 유지한다. 카드만 수정하면 원본 기록은 유지한다. 포트폴리오는 자동 변경하지 않는다.
- Mock은 기록의 역량 태그를 카드와 별도로 보관한다. 이전 저장소는 기존 카드의 태그로 한 번 복원한 뒤 분리하며 데이터를 초기화하지 않는다. 기록을 다시 수정하면 원본 기록의 태그로 카드를 갱신한다.
- 프로젝트 요청의 401은 AuthProvider의 기존 세션 해제·로그인 이동으로 연결한다. 취소된 요청, 401 이외의 오류, 로그인 상태 변경 전에 시작된 이전 요청의 지연 401은 현재 세션을 해제하지 않는다. 로그인·탈퇴 재인증 요청에는 이 알림을 적용하지 않는다.
- 기록 추가 폼의 열림 상태는 프로젝트 상세에서 유지한다. 저장·취소·포트폴리오 진입 때 닫고, 포트폴리오 완료 후 재마운트되어도 다시 열지 않는다. 목록에서 새로 들어오는 기록 추가 링크는 계속 폼을 연다.
- H-16~H-18: 모든 기록 기본 선택 → 선택 기록 기반 질문·초안 → Markdown 수정·복사·저장. 포트폴리오 생성으로 카드를 추가하지 않는다.
- #36: 마치기 질문의 quote는 일반 질문과 산출물 요청 모두에 표시한다. answer가 null이면 빈 입력이며, 같은 질문의 미저장 입력만 유지하고 서버 답변·상태가 바뀌면 서버 값을 복원한다. 산출물 ANSWERED 상태에서 첨부 목록을 반환하지 않는 계약 때문에 파일 정보를 지어내지 않고 '기존 산출물로 다음'으로 이어 간다. questions가 비면 질문 화면을 생략해 같은 recordIds로 초안을 생성하며, 실패 시 초안 요청만 재시도한다. 질문이 없던 검토 화면의 뒤로가기는 기록 선택으로 돌아간다.
- #36: 초안은 서버 markdown을 그대로 편집기에 넣고 role·contribution·problem·result·artifact·learned를 각각 내 역할·주요 기여·문제와 해결·결과·산출물·배운 점으로 안내한다. blanks가 비면 안내를 표시하지 않는다. 답변 PATCH 성공 후 초안을 다시 요청하며, 완료/포트폴리오 저장은 34번 API 성공 시에만 반영한다. 인증은 기존 세션 쿠키·CSRF 흐름을 그대로 사용한다.
- H-25: 프로젝트 삭제는 확인 후 처리하고 목록 이동·토스트를 제공한다. 포트폴리오 단독 삭제는 API 명세에 없어 제공하지 않는다.
